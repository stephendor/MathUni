Functors (cat-03)

cat-01 built categories and cat-02 used them, but both worked inside a single category at a time. Aluffi's §5.2 admitted the cost: the honest account of a universal property "requires a good familiarity with the language of functors", and he deferred them to this chapter. Here they are. A functor moves objects to objects and arrows to arrows, preserving identities and composition — which sounds like bookkeeping until you notice what it licenses. Functors compose. And once they compose, a filtration of spaces and the homology functor can be joined into a single object: a group for every parameter value and a map for every comparison.

Predict before we start. Homology is a functor. "Sample the filtration at level t" also names a functor. Predict: does composing them give a persistence module?

It depends. The phrase can name the filtration itself, 𝒳 : P → Top, whose value at t is Xt; or it can name evaluation at t, evt : TopP → Top, which takes a whole filtration and returns one space. Both are functors and both compose with Hn, but Hn ∘ 𝒳 has domain P and is a persistence module, while Hn ∘ evt has domain TopP and produces one abelian group. Composing is a type-checking operation before it is a mathematical one. Segment 3 does both computations.

Why this matters for the mission: Homology is a functor; so is 'sample the filtration at level t'. Persistence composes the two.

What this unit's sources do and do not establish. The mission strip is quoted verbatim, as the rubric requires, and for the first time in the cat module most of it is within reach — because functors are finally available and functors are what the strip is about.

"Homology is a functor" is true and is not established here. Neither Aluffi §VIII.1 nor Spivak ch. 3 contains homology. at1-10 established it from Hatcher §2.3, where 𝟙∗ = 𝟙 and (fg)∗ = f∗g∗ are exactly Definition 1.1's two conditions. This lesson takes it from there and does not reprove it.

"Persistence composes the two" is correct under one reading of the strip and false under the other, and the ambiguity is worth resolving rather than passing over. Composition of functors is available here — Aluffi's Definition 1.1 gives the conditions and Spivak works a composite explicitly on p. 101 — so the check can be made. It is a check on domains: Hn ∘ 𝒳 has domain P and is a group for each index with a map for each comparison, which is a persistence module; Hn ∘ evt has domain TopP and yields a single group. Both composites exist. Only the first is persistence. The guided proof does both and Problem 5(e) makes the reader do them again.

Still not established here: persistence itself. No filtration, barcode, interval decomposition or stability statement appears in either source, and the word persistence appears in neither. What this unit adds to at1-10's version of the same observation is the definition that makes the composite legitimate rather than suggestive — at1-10 formed the composite before this module had defined a functor at all, and said so.

Segment 1 · ~25 min

One definition, two notations

Definition 1.1 (Aluffi). A covariant functor ℱ : C → D assigns an object ℱ(A) of D to every object A of C, and a function HomC(A, B) → HomD(ℱ(A), ℱ(B)) to every pair A, B, such that ℱ(1A) = 1ℱ(A) for all A, and ℱ(β ∘ α) = ℱ(β) ∘ ℱ(α) whenever the composite is defined. — Aluffi §VIII.1.1, p. 484

Definition 3.35 (Spivak). To specify a functor F : 𝒞 → 𝒟: (i) for every object c of 𝒞 specify an object F(c) of 𝒟; (ii) for every morphism f : c1 → c2 specify a morphism F(f) : F(c1) → F(c2). These must satisfy (a) F(idc) = idF(c), and (b) F(f ; g) = F(f) ; F(g). — Spivak §3.3.2, p. 91

These are the same definition. The only difference is the order of composition: Spivak's f ; g means "first f, then g", Aluffi's β ∘ α means the same composite written the other way about. Both conventions are standard — classical algebra writes ∘, the applied category theory this degree draws on writes ; — and the one thing you must not do is mix them inside a single argument. Fix one at the start of any calculation.

A contravariant functor C → D is, by Aluffi's definition, a covariant functor Cop → D. Unwound, it sends α : A → B to 𝒢(α) : 𝒢(B) → 𝒢(A) and satisfies 𝒢(βα) = 𝒢(α)𝒢(β) — note the switch. Aluffi draws it: A → B → C goes to 𝒢(A) ← 𝒢(B) ← 𝒢(C). In both variances, commutative diagrams go to commutative diagrams, because commutativity is an equation between composites and both conditions are equations about composites.

Self-check 1. Why do functors send commutative diagrams to commutative diagrams?

Preservation of composites. If two paths through a diagram compose to the same morphism, applying ℱ to that equation gives an equation between the images of the two composites, and preservation turns each into the composite of the images. Contravariant functors reverse every arrow but still send commuting diagrams to commuting ones — Aluffi says so explicitly — because the reversed equation is still an equation. Nothing here needs injectivity, and identities alone would not suffice.

Examples come in two flavours. The forgetful functors drop structure: a ring has an underlying abelian group, and a ring homomorphism is in particular a homomorphism of those groups, so Ring → Ab is a covariant functor. Then there are the ones that do something. Example 1.2: R ↦ R∗, the group of units, is a covariant functor Ring → Grp. Example 1.4: Spec, the set of prime ideals, is contravariant, because a ring homomorphism φ : R → S pulls prime ideals back, giving φ∗ : Spec(S) → Spec(R).

Worked, then fading: the two Hom functors. — Aluffi §VIII.1.2, p. 486

Fix an object X of C. Then A ↦ HomC(X, A) is covariant and A ↦ HomC(A, X) is contravariant.

Covariant case. Given α : A → B, we need a function Hom(X, A) → Hom(X, B). There is exactly one thing to do: send φ : X → A to αφ : X → B. That is post-composition. It preserves identities, since 1Aφ = φ; and it preserves composition, since (βα)φ = β(αφ).

Contravariant case. Given α : A → B, we need a function Hom(B, X) → Hom(A, X) — note the direction. Again there is one thing to do: send ψ : B → X to ⟨ … ⟩, which is pre-composition. It preserves identities because ⟨ … ⟩. For composition, take α : A → B and β : B → C and a morphism ψ : C → X; then applying the functor for βα gives ⟨ … ⟩, while applying it for β and then for α gives ⟨ … ⟩ — the same morphism, in the reversed order, which is exactly 𝒢(βα) = 𝒢(α)𝒢(β).

Aluffi calls these "an important class of functors that are available on any category", and says they will be a source of examples for the next few sections. They are: cat-04's Yoneda lemma is a statement about exactly these.

Segment 2 · ~25 min

Spivak's functors: schemas, instances, and how much is forced

Spivak arrives at functors from databases, and the route is worth taking because it makes the definition concrete. His observation: a database schema is a category — objects are tables, morphisms are columns pointing at other tables — and the data filling that schema is an assignment of a set to each table and a function to each column.

Definition 3.44 (Spivak). Let 𝒞 be a schema, that is, a finitely presented category. A 𝒞-instance is a functor I : 𝒞 → Set. — Spivak §3.3.3, p. 93

His summary: "a database schema is a category, and an instance on that schema — the data itself — is a set-valued functor. All the constraints, or business rules, are ensured by the rules of functors, namely that functors preserve composition." That is a genuine engineering claim and it has a genuine limit. Path equations declared in the schema are enforced automatically, because a functor must send equal composites to equal composites. Conditions that are not equations between composites — that a column be injective, that a table be non-empty — are not enforced by anything in Definition 3.35.

Example 3.36 draws three functors 2 → 3 and notes something that is true of all of his early examples: each is completely determined by what it does on objects. Example 3.38 is sharper — there is exactly one functor from the free square category to the commutative square category sending A′ ↦ A and so on, and once that decision is made "each of the ten paths in F is forced to go to a certain path in C". Then Spivak adds the corrective: "All of our example functors so far have been completely determined by what they do on objects, but this is usually not the case."

Why his examples were forced, and why yours will not be. In 2, 3 and the commutative square, there is at most one morphism between any two objects. So once the objects are placed, every Hom-set the functor must map into is a singleton and no choice remains — the same phenomenon that made every morphism a monomorphism in cat-01's Example 4.10. Take a category where Hom-sets are large and the situation inverts completely: a functor between one-object categories is a group homomorphism, the object assignment carries no information whatever, and the morphism assignment is the entire content.

Self-check 2. Spivak says functoriality enforces a database's business rules. Which of these does it not enforce?

Injectivity. Definition 3.35 constrains a functor by two equations — identities go to identities, composites to composites — and every rule it enforces is therefore an equation between composites. Injectivity is not one: nothing in the definition says anything about how many elements a set has or whether a function collapses any of them. The other three options are all path equations or identity conditions, and all are automatic.

Self-check 3. Aluffi defines an equivalence of categories as a fully faithful, essentially surjective functor rather than as a bijection on objects and morphisms. Why the weaker condition?

Different sizes. Example 1.8's matrix category has one object per non-negative integer; the category of finite-dimensional k-vector spaces has a proper class of objects. No bijection on objects is possible, yet the two carry the same information — the functor is fully faithful and every finite-dimensional space is isomorphic to some kn, which is all essential surjectivity asks. "Isomorphic to" rather than "equal to" is exactly the slack that makes the notion useful.

Segment 3 · ~30 min

Composition, and which composite is persistence

Spivak works a composite explicitly on p. 101. He has a functor F : Gr → DDS between two schemas, and an instance I : DDS → Set. Then: "Objects in Gr are sent by F to objects in DDS, which are sent by I to objects in Set, which are sets. Morphisms in Gr are sent by F to morphisms in DDS, which are sent by I to morphisms in Set, which are functions. This defines a composite functor." The result is an instance on Gr — data migrated from one schema to another by nothing more than composing.

That functors compose at all is a two-line check, and it is the whole engine of what follows.

Guided proof. First prove that the composite of two functors is a functor. Then use it to settle the mission strip: compute both candidate composites with Hn and say which one is a persistence module. Write your argument before revealing the model answer.

Reveal the model answer

Composites are functors. Let F : C → D and G : D → E. On objects, (G∘F)(A) = G(F(A)). On morphisms, (G∘F)(α) = G(F(α)), which runs from G(F(A)) to G(F(B)) as required. Identities: (G∘F)(1A) = G(F(1A)) = G(1F(A)) = 1G(F(A)). Composition: (G∘F)(βα) = G(F(β)F(α)) = G(F(β))G(F(α)). Each condition is used once in each factor. ∎

Setting up. Let (P, ≤) be a preorder as a category — cat-01's Example 3.3, which needs only reflexivity and transitivity. A functor 𝒳 : P → Top assigns a space Xp to each p and a continuous map Xp → Xq to each p ≤ q, with identities and composites matching; a nested family of subspaces with inclusions is exactly such a functor. And Hn : Top → Ab is a functor, established in at1-10 from Hatcher §2.3.

First composite. Hn ∘ 𝒳 : P → Ab. Domain P, codomain Ab. Its value at p is Hn(Xp); its value on p ≤ q is the induced homomorphism Hn(Xp) → Hn(Xq). So: one abelian group for every index, one homomorphism for every comparison, compatible under composition. That is a persistence module.

Second composite. Evaluation at t is a functor evt : TopP → Top from the category whose objects are filtrations, sending 𝒳 to Xt. So Hn ∘ evt : TopP → Ab. Domain TopP, codomain Ab. Its value at a filtration 𝒳 is the single group Hn(Xt). That is one abelian group, not a persistence module — it is the t-th slice, and it contains no comparisons at all.

Verdict. Both composites are legitimate functors, so the strip is not false; but only the first is persistence. The strip's phrase "sample the filtration at level t" most naturally names evaluation, which is the wrong one. Read as naming the filtration itself, it is right. ∎

What to notice. The whole argument was settled by looking at domains and codomains, before anything mathematical happened. Naming two functors does not determine a composite: you must say which two and in which order, and the types have to meet. at1-10 made a version of this point by counting arrows; this unit can make it properly, because it now has the definition that says what composing means.

Self-check 4. In the composite Hn ∘ 𝒳 : P → Ab, which of the two functors did this module construct?

Neither, and that is the honest answer. Aluffi and Spivak contain no homology and no filtrations. What cat-03 adds over at1-10 is not a new arrow but the licence to compose: Definition 1.1 says what a functor is, the guided proof shows composites are functors, and only then is "Hn ∘ 𝒳" a defined expression rather than a suggestive one. at1-10 formed it before this module had defined a functor, and said so at the time.

Self-check 5. Aluffi calls HomC(X, −) and HomC(−, X) "available on any category". What makes them available with no hypotheses at all?

Composition alone. The covariant one acts on morphisms by post-composition and the contravariant one by pre-composition, and both operations exist in every category by axiom. The Hom-sets land in Set because Definition 3.1 required HomC(A, B) to be a set, which is exactly the clause cat-01 flagged as doing unobtrusive work. These functors are the subject of cat-04's Yoneda lemma.

Reveal the skeleton

1. A functor is two assignments and two equations. Objects to objects, morphisms to morphisms, with ℱ(1) = 1 and ℱ(βα) = ℱ(β)ℱ(α) — Aluffi's Definition 1.1 and Spivak's Definition 3.35, the same thing in ∘ and ; notation. Contravariance is covariance on Cop and reverses composition. Both variances send commuting diagrams to commuting diagrams, because commutativity is an equation between composites. Forgetful functors, R ↦ R∗, Spec (contravariant), and the two Hom functors, which exist in every category because they are built from composition alone.

2. Everything a functor enforces is an equation between composites. Spivak's schemas make this concrete: a database instance is a functor 𝒞 → Set, and functoriality automatically enforces every declared path equation — and nothing else. Injectivity and cardinality conditions are invisible to it. His early examples are determined by their action on objects only because their Hom-sets have at most one element; for one-object categories the object assignment carries nothing and the morphism assignment is everything. Fully faithful plus essentially surjective is equivalence, weaker than bijection because Example 1.8 matches one object per dimension against a proper class of vector spaces.

3. Functors compose, and composing is a type check first. (G∘F)(1) = 1 and (G∘F)(βα) = G(F(β))G(F(α)), each condition used once per factor. Applied to the mission: with P a preorder as in cat-01's Example 3.3, a filtration is a functor 𝒳 : P → Top, and Hn ∘ 𝒳 : P → Ab is a group per index and a map per comparison — a persistence module. But evaluation at t is also a functor, evt : TopP → Top, and Hn ∘ evt : TopP → Ab yields a single group. Both composites are legitimate; only one is persistence, and the domains decide which.
