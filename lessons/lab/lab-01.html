Setup and point clouds (lab-01)

Eighty points, sampled from a circle. You are about to detect the hole, and the first honest thing this module can tell you is that the hole is not there. As a topological space the data is eighty separate points — no loop, no connectivity, nothing. That is not a defect of the sample or of the noise; it is what a finite set of points always is. Whatever the pipeline finds, it does not find it in the data's topology, because the data has none. This unit installs the toolkit and then spends its time on where the topology actually comes from.

Predict before we start. Eighty points are sampled with noise from a circle. What is H₁ of that set of eighty points, with its usual metric?

Zero. Take the smallest distance between two of the eighty points — for this sample the code returns 0.004290 — and put a ball of half that radius around each point. Each ball holds exactly one point, so every singleton is open, so every subset is open: the topology is discrete. A discrete space on eighty points is eighty contractible pieces, so H₀ = ℤ⁸⁰ and everything above vanishes. Noise is irrelevant to this: it is true for any finite set of distinct points, at any noise level, including none. The last option is wrong for a subtler reason worth keeping — a point set does have a well-defined homology, and the answer is simply uninteresting.

Why this matters for the mission: A point cloud is a finite metric space; every pipeline in this lab starts exactly here.

The strip is true, and this unit's job is to say what it is worth.

The first clause is exactly right, and the problem set verifies it by running it. A point cloud is a finite metric space: pdist on the eighty points returns a matrix satisfying all three clauses of an2-01's Definition 3.1.1, with zero triangle violations across all 512 000 triples.

But a finite metric space is where metric-space theory goes to die. an2-02's completeness holds trivially, because a Cauchy sequence in a discrete space is eventually constant. an2-03's compactness holds trivially, because every sequence in a finite set has a constant subsequence. Every function out of it is continuous. A hypothesis satisfied by everything in sight separates nothing, so none of these facts can distinguish this point cloud from any other.

What the strip does not say is where the content is. It is in the scale parameter: not one space but a one-parameter family, and the topology belongs to the family. No syllabus action — the strip is accurate and incomplete, and the incompleteness is the subject of the next eight units.

Not claimed here. That the long bar this unit produces means the circle. That is an inference, it needs a theorem, and the theorem is lab-05's.

Segment 2 · 25 min

What the data is, and what it is not

Worked — the point cloud is a metric space, checked rather than asserted.

squareform(pdist(X)) returns the 80 × 80 matrix D of pairwise distances. Against an2-01's Definition 3.1.1:

(i) the diagonal is exactly zero and every off-diagonal entry is strictly positive — so d(x, y) = 0 if and only if x = y, both halves. (ii) np.array_equal(D, D.T) is True. (iii) across all 80³ = 512 000 triples, zero violations of d(i, j) ≤ d(i, k) + d(k, j).

Two remarks that matter more than the result. First, the tolerance: the check compares with a slack of 1e-12, because floating-point addition is not associative and an exact comparison would be testing the arithmetic rather than the axiom. Second, and this is the point — the check could not have failed. The distances came from pdist on points in ℝ², and a subset of a metric space is a metric space. So the run is evidence about the library, not about the mathematics. That is the whole of what executing a known theorem can buy, and it is still worth buying.

Now the number that changes the subject. The smallest distance between two distinct points of this sample is 0.004290, and the diameter is 2.233080.

Every finite metric space is discrete. Let r be the smallest distance between distinct points. Then B(x; r/2) = {x} for every x, so every singleton is open, so every subset is open. Checked by execution on this sample: every B(x, r/2) is a singleton: True. Proved in one line, and the one line is the whole of what a point cloud's topology has to say.

The consequences are worth writing down flatly, because each one is a result the reader spent real time on:

Three yeses that buy nothing. This is not a complaint about an2; it is the reason the module is arranged the way it is. A hypothesis that every object satisfies cannot distinguish any object from any other, and every point cloud satisfies all three. So the theory is not being applied to the data. Segment 3 says what it is being applied to.

Self-check 2. The cloud was sampled from a circle. The circle has H₁ = ℤ; the cloud has H₁ = 0. Which is the right response?

Both statements are correct. A million points sampled from the circle still form a discrete space with H₁ = 0, and so do a million points sampled with no noise at all — the first two options fail for the same reason, and neither noise nor sample size is the variable. What the reader wants is not the homology of the points but the homology of the circle the points came from, and that is not determined by the points. It is inferred, at a scale, with a guarantee. Getting from one to the other is the entire module, and lab-05 is where the guarantee arrives.
Guided — predict the shape of the answer before you run anything.

You are about to run Vietoris–Rips persistence in degrees 0 and 1 on these eighty points. Before reading on, write down three predictions, and commit to numbers rather than adjectives.

1. How many H₀ intervals will come back? 2. How many H₁ intervals? 3. Of the H₁ intervals, how will their lifetimes be distributed — and what would you need to see to call one of them a hole?
What the run actually returns H₀: 79. Not 80. That is a library convention, not a fact about the data, and it is Segment 3's subject.

H₁: 6. Not 1. All six are genuine 1-cycles in a genuine complex — little gaps between neighbouring points that briefly fail to fill in. Nothing in the algorithm marks any of them as noise.

The lifetimes split, and only by degree. The longest is 1.2370, from birth 0.3991 to death 1.6361. The runner-up is 0.0126. The ratio is 98.1, and that ratio is the entire evidence that one of the six is different in kind from the other five. If you predicted "one long bar and some short ones", you were right about the shape; the thing to notice is that you were predicting a ranking, not a classification, and that persistence gives you nothing else. If the ratio had come back 1.4, the honest conclusion would be that the data does not distinguish them.

Segment 3 · 25 min

Where the topology comes from, and one number that is the library's

The input had no topology. The output has a bar of length 1.2370. The parameter that appears nowhere in the coordinates is the scale: the pipeline does not ask what shape the points form, it builds a complex at every radius at once and records the radii between which a 1-cycle exists. 1.2370 is the width of the band of radii on which the eighty points are connected enough to close a loop and not yet connected enough to fill it. It is a fact about a family of spaces, and there is no single space it is a fact about.

The data, and its six intervals. Left: the eighty points. The two rings on one point are radius 0.20, where the complex is still in pieces, and radius 0.3991, the radius at which the long 1-cycle is born. Right: all six H₁ intervals on one radius axis. The long one is 170 px wide; the other five are 2, 2, 1, 1 and 1 px, against an axis running to 1.75. That disparity is the figure's whole content. Nothing has been dropped and the axis is not rescaled — but two of the five are drawn wider than they are: at this scale their true widths are 0.84 and 0.43 of a pixel, and a sub-pixel bar paints as nothing at all, so both are clamped up to one pixel. Read the figure as "five intervals too short to see" and the printed lifetimes as the record of how short. A picture that tells the truth about the ratio would have to omit them, which would tell a worse lie.

Faded — the missing eightieth interval. giotto-tda 0.6.2, reduced_homology.

Eighty points, and the run reports 79 intervals in H₀. Setting reduced_homology=False reports 80. The points did not change.

The dropped interval is the essential class: the one connected component that never dies. Under reduced_homology=False it appears with death ∞; reduced homology quotients out the extra generator of H̃₀ and it vanishes.

⟨your step: reduced_homology=True is the default. Write the rule this imposes, in the form an2 used for pages — and then decide which of these two sentences you are willing to put in a later unit: "the number of H₀ bars equals the number of connected components", or the same sentence with something added.⟩

Self-check 3. A later unit reports "the number of H₀ bars equals the number of connected components", citing giotto-tda. Is it right?

It is true under reduced_homology=False and false by exactly one under the default, which is True. So the second option is wrong to say "always" — under the other flag the sentence is exactly right. The trouble is that a reader of the sentence alone cannot tell which world they are in, because the flag is invisible at the call site and the version is unstated. This is the lab's version of a citation with no page number, and the default is the dangerous half: a non-default argument at least appears in the code you can read.

Self-check 4. Six H₁ intervals came back and the circle has one hole. What is the status of the other five?

All six are real. Each is an honest 1-cycle that appears at one radius and is filled at another — the short ones are gaps between neighbouring points that briefly fail to fill in. No arithmetic went wrong, no library misbehaved, and a noiseless sample of eighty points spaced around a circle would produce short intervals too, since the spacing itself creates them. What separates the first from the rest is 1.2370 against 0.0126: a ratio of 98.1, and a ratio is a matter of degree. Persistence hands you a ranking and no threshold. The threshold is the reader's, until lab-05 supplies a theorem that constrains it.

Self-check 5. If a semester of metric-space theory is trivial on every point cloud, what was it for?

To the diagrams. The data is a finite metric space and everything about it is trivial; the output of the pipeline is a persistence diagram, and diagrams live in a space where nothing is trivial — an2-01 established that the bottleneck distance on diagrams in general is an extended pseudometric, with distinct diagrams at distance zero and values in [0, ∞], and an2-02 audited exactly what completeness does and does not mean there. lab-05 needs that vocabulary to state stability at all. The inversion is worth saying out loud because the syllabus order hides it: the input is the trivial metric space and the output is the hard one. The third option is wrong on a detail — the Vietoris–Rips complex on a finite set is finite at every radius; it is the family that is infinite, and a family is not a metric space.
