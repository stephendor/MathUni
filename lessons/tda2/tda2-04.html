Distances for multiparameter persistence (tda2-04)

Stability needs a metric. Interleaving generalises to d parameters word for word; actually computing it is another matter entirely.

Every stability theorem in tda1 had the same shape: perturb the input a little, and the barcode moves a little, measured in the bottleneck distance. That whole apparatus rested on the barcode existing. tda2-02 removed it.

So which of the two ingredients survives? Remarkably, the distance does. The interleaving definition never mentions intervals, never mentions barcodes, and never mentions the number of parameters — it is a statement about two families of maps and two commuting diagrams, and it reads identically for d = 1 and d = 7. What does not survive is the ability to compute it.

Prediction gate — commit before reading on. In one parameter, the interleaving distance is computable because it coincides with a bottleneck distance between barcodes, which is a matching problem. With no barcode available for d ≥ 2, predict how hard computing the interleaving distance becomes.

Correct. Theorem 12.1 says that computing a real r with dI(M,N) ≤ r < 3 dI(M,N) is NP-hard, for modules given by graded matrix representations. That is an approximation-hardness statement, strictly stronger than hardness of exact computation, and it is what forces the rest of the chapter: the matching distance and the bottleneck distance both exist because this one cannot be computed. Note it is hardness, not undecidability — the problem is perfectly decidable, just not tractably.

Why this matters for the mission: The interleaving distance is defined categorically (cat-07's functor viewpoint) and extends verbatim to d parameters, but unlike tda1-06's one-parameter case it is not obtained from a matching of intervals. The matching distance is a tractable lower bound, and bottleneck distance returns only for interval-decomposable modules.

Segment 1 · ~25 min

The categorical definition, and why it does not care about d

Dey and Wang restate persistence in categorical language before defining any distance, and the reason becomes clear immediately: the definition that generalises is the one that never mentioned intervals in the first place.

Definition 12.1 (category). A category 𝓒 is a set of objects Obj 𝓒 with a set of morphisms hom(x,y) for every pair x, y ∈ Obj 𝓒, where for every x there is an identity morphism 𝟙x ∈ hom(x,x), and if f ∈ hom(x,y) and g ∈ hom(y,z) then the composite lies in hom(x,z). — Dey & Wang §12.1, Definition 12.1, pp. 367–368

Definition 12.2 (functor). A functor F : 𝓒 → 𝓓 assigns F(x) ∈ Obj 𝓓 to every x ∈ Obj 𝓒 and F(f) ∈ hom(F(x),F(y)) to every f ∈ hom(x,y), respecting composition and identities. — Dey & Wang §12.1, Definition 12.2, p. 368

Definition 12.3 (natural transformation). Given functors F, G : 𝓒 → 𝓓, a natural transformation η : F ⟹ G is a family of morphisms {ηx : F(x) → G(x)} for every object x making the evident square commute. — Dey & Wang §12.1, Definition 12.3, pp. 368–369

Definition 12.4 (persistence module). Let ℙ be a poset category. A ℙ-indexed persistence module is a functor M : ℙ → Vec. If M takes values in vec, M is pointwise finite-dimensional. The ℙ-indexed persistence modules form a category in which the natural transformations are the morphisms. — Dey & Wang §12.1, Definition 12.4, p. 369

Unpack that for a filtration. The poset category has one morphism x → y exactly when x ≤ y, so a functor to vector spaces assigns a space to each parameter value and a linear map to each comparison, with the map for x ≤ z equal to the composite through any intermediate y. That is precisely the compatibility a filtration's induced maps satisfy — and stating it as functoriality is what makes the number of parameters irrelevant, since ℙ can be ℝ, ℝd, or anything else.

Definition 12.5 (finite type). A ℙ-indexed persistence module M has finite type if it is pointwise finite-dimensional and all morphisms M(x ≤ y) are isomorphisms outside a finite subset of ℙ. Throughout, the poset category is ℝd with the standard partial order and all modules are of finite type. — Dey & Wang §12.1, Definition 12.5, p. 369

Interleaving

Definition 12.6 (shift). For δ ∈ ℝ write δ⃗ = (δ, …, δ) = δ · e⃗. The shift functor (·)→δ on ℝd-modules produces M→δ, the module translated diagonally by δ in every coordinate at once. — Dey & Wang §12.2, Definition 12.6, p. 369

Definition 12.7 (interleaving). For d-parameter modules M and N and δ ≥ 0, a δ-interleaving is a pair of families of linear maps φ = {φx : Mx → Nx+δ⃗} and ψ = {ψx : Nx → Mx+δ⃗} satisfying two conditions. Triangular commutativity: the two composites return the module's own structure map shifted by 2δ. Rectangular commutativity: φy ∘ ρMx→y = ρNx+δ⃗→y+δ⃗ ∘ φx, and the same for ψ. — Dey & Wang §12.2, Definition 12.7, pp. 369–370

Definition 12.8 (interleaving distance). dI(M,N) = infδ{M and N are δ-interleaved}. If they are not δ-interleaved for any δ ∈ ℝ+ we call them ∞-interleaved and set dI(M,N) = ∞. — Dey & Wang §12.2, Definition 12.8, p. 370

Now look back at what was just written and count the places d appears. In the shift, which is a vector rather than a scalar; and in the index poset. Nowhere else. Both commutativity conditions are word for word the one-parameter conditions of tda1-06. That is what "extends verbatim" means, and it is a direct consequence of having defined the distance in terms of maps rather than in terms of a decomposition.

Visual: the two commuting conditions

Theorem 12.1. Given two modules M and N given by graded matrix representations, the problem of computing a real r so that dI(M,N) ≤ r < 3 dI(M,N) is NP-hard. — Dey & Wang §12.2, Theorem 12.1, p. 370

Read the quantifier structure carefully, because the theorem is stronger than it first appears. It does not say the exact value is hard to compute; it says that any value within a factor of 3 is hard to compute, and exact computation is the special case r = dI. It also does not say the problem is undecidable — it is perfectly decidable, just not tractably so. And the statement is tied to an encoding: the modules are given by graded matrix representations as in Chapter 11, which Dey and Wang note coincide with the modules of finite type. A complexity claim without an encoding would be empty.

Self-check 1. Which part of Definition 12.7 changes when d increases from 1 to 2?

Rectangular commutativity is a single condition quantified over all comparable pairs x ≤ y — increasing d increases how many such pairs there are, but adds no clause to the definition. The third option gets the situation exactly backwards: the interleaving definition never mentioned matchings, which is precisely why it survives. It is the bottleneck distance that needs a matching, and that is what fails to generalise.

Self-check 2. Theorem 12.1 rules out which of the following?

Hardness is not undecidability, so the first option is too strong. The third is also too strong, and its falsity is the whole architecture of §12.4: restricting to interval decomposable modules is exactly the escape route the chapter takes. What is ruled out is a general polynomial-time 3-approximation.

Two computable substitutes

Matching distance: slice into lines

The matching distance takes the restrictions of M and N over lines of positive slope and forms the supremum of weighted interleaving distances on those restrictions. Each restriction is a one-parameter module, so each carries a barcode and each interleaving distance is computable.

Restriction and weight. For a line ℓ : y = sx + t with s > 0, parameterise by λ(x) = (1/(1+s²))(x, sx+t) and set M|ℓ(x) = M(λ(x)) with the induced maps, a one-parameter persistence module. Define

w(ℓ) = 1/√(1+s²) for s ≥ 1,   w(ℓ) = 1/√(1+1/s²) for 0 < s < 1.

— Dey & Wang §12.3, pp. 370–371

The λ above is quoted exactly, and it is loose. Two things are off, and noticing them is good practice. First, as literally written λ does not land on ℓ at all unless t = 0: the point (x/(1+s²), (sx+t)/(1+s²)) satisfies y = sx + t only when t/(1+s²) = t. The scaling has been applied to the intercept as well as to the direction. Second, the factor is not the one that makes the parameterisation unit-speed. The direction vector of ℓ is (1, s) with norm √(1+s²), so the arc-length parameterisation is λ(x) = (0,t) + (x/√(1+s²))(1,s) — the square root, applied to the direction only, with the intercept added unscaled. The tell is on the page itself: the weight w(ℓ) directly below uses 1/√(1+s²), and it would be a strange design for the parameterisation and the weight that corrects it to disagree by a square root.

Nothing downstream in this unit turns on it. Definition 12.9 takes a supremum of w(ℓ)·dI(M|ℓ, N|ℓ), and what carries the stability claim is the weight; the restriction only has to name the same one-parameter module, which any faithful parameterisation of ℓ does. The reason to flag it rather than quietly print the repaired formula is that you will meet the printed one when you read §12.3, and a reader who "corrects" it to 1/√(1+s²) without also moving the intercept out of the scaling has fixed the square root and kept the real error.

Definition 12.9 (matching distance). dm(M,N) = supℓ∈Λ{w(ℓ) · dI(M|ℓ, N|ℓ)}, the supremum over all lines of positive slope. The weight w(ℓ) is introduced to make the matching distance stable with respect to the interleaving distance. — Dey & Wang §12.3, Definition 12.9, p. 371

What §12.3 states, and what it does not. Dey and Wang say the weight makes dm stable with respect to dI, and go on to give a polynomial-time algorithm computing dm for two-parameter modules. They do not display an inequality between dm and dI in either direction in this section. This unit's mission strip describes dm as a tractable lower bound; the tractability is established here, the precise comparison is not, and this lesson does not supply it. Where the algorithm comes from is §12.3.1's point-line duality and its arrangement of O(n⁴) lines, deferred here.

The idea is worth weighing on its own terms. What is gained is decisive: a supremum over a suitably chosen finite family of lines is computable in polynomial time, which Theorem 12.1 says dI itself is not. What can be lost is anything invisible along every single line — the module is probed only on one-dimensional slices, and slices are exactly the kind of summary tda2-03 warned may fail to separate non-isomorphic modules.

Bottleneck distance: restrict the modules instead

Definition 12.12 (matching). A matching μ : A → B between two multisets is a partial bijection, that is μ : A′ → B′ for some A′ ⊆ A and B′ ⊆ B; we write im μ = B′ and coim μ = A′. — Dey & Wang §12.4, Definition 12.12, pp. 374–375

Definition 12.13 (bottleneck distance). Let M ≅ ⊕i=1mMi and N ≅ ⊕j=1nNj be decompositions into indecomposables, with I = {1,…,m} and J = {1,…,n}. M and N are δ-matched for δ ≥ 0 if there is a matching μ : I → J under which matched summands are δ-interleaved and unmatched summands are δ-interleaved with the zero module; db is the infimum of such δ. — Dey & Wang §12.4, Definition 12.13, p. 375

Fact 12.2. One has dI ≤ db. — Dey & Wang §12.4, Fact 12.2, p. 375

The direction is the intuitive one. A matching exhibits the interleaving summand by summand, so any δ-matching gives a δ-interleaving and the infimum over matchings can only be larger. The converse fails because a genuine interleaving of the whole modules is free to mix summands, and no matching need exist realising it. So the bottleneck distance is the coarser measurement, and it bounds the interleaving distance from above.

Worked example 1: where a matching can even be attempted

Example. Definition 12.13 presumes decompositions into indecomposables. tda2-03 established that these exist and are essentially unique by Krull–Schmidt, but that the indecomposables are not classified. Why does §12.4 nevertheless get an algorithm?

Step 1 — the obstacle. A matching pairs summands of M with summands of N and then asks whether each matched pair is δ-interleaved. Both operations need the summands to be objects one can name, store and compare. Unclassified indecomposables are none of those things.

Step 2 — the restriction. Definition 12.14: an interval is a non-empty I ⊂ ℝ̄d that is order-convex — p, q ∈ I and p ≤ r ≤ q imply r ∈ I — and order-connected, any two of its points being joined by a finite chain inside I whose consecutive terms are comparable. Definition 12.15: a d-parameter interval module has Mx = 𝐤 for x ∈ IM and 𝟎 otherwise, with identity structure maps within IM. Definition 12.16: a module is interval decomposable if it decomposes into interval modules.

Step 3 — why that is the right class. An interval module is determined by a subset of ℝ̄d, which is nameable, storable and comparable. So on this class the summands are exactly the kind of object a matching needs, and the algorithm becomes possible — at the cost of a hypothesis on the input.

Step 4 — the simplest intervals. Definition 12.17: a k-rectangle in ℝd is a product [a1,b1] × ⋯ × [ad,bd] in which exactly k of the factors are non-degenerate, a 0-rectangle being a point. Rectangles are order-convex and order-connected automatically, so rectangle-decomposable modules form a subclass of the interval decomposable ones — the multiparameter analogue of tda1-04's intervals.

Worked example 2 (faded): what a bottleneck computation entitles you to say. Two two-parameter modules are computed from two data sets, both verified interval decomposable, and an algorithm returns db(M,N) = 0.4.

The bound. By Fact 12.2, dI ≤ db, so the interleaving distance is at most ⟨your step: what value?⟩. The two modules are therefore genuinely close in the interleaving distance.

The non-bound. Now suppose instead the algorithm returns db(M,N) = 12. Since Fact 12.2 bounds dI only from ⟨your step: above or below?⟩, this says ⟨your step: what about dI?⟩.

The hypothesis. Both readings assume interval decomposability, which is a property of the modules and not of the algorithm. It has to be verified on the input, not inferred from the output — an algorithm handed a non-decomposable module will still return a number.

Gap solutions: at most 0.4; from above only; so a large db is not by itself evidence that dI is large.

You try (solo). Let M be the interval module on the rectangle [0,2] × [0,2] and N the interval module on [1,3] × [1,3] in ℝ². (i) For which δ does the diagonal shift by δ⃗ carry IM into IN and back? (ii) Use that to give an upper bound on dI(M,N) directly from Definition 12.7, saying which maps you take as φ and ψ. (iii) Now consider N′, the interval module on [1,3] × [0,2] — shifted in one coordinate only — and explain why the diagonal shift of Definition 12.6 makes this case less comfortable.

Hint: for (iii), note that δ⃗ moves every coordinate by the same amount, so a purely horizontal displacement must be absorbed by a diagonal shift large enough to cover it.

Proposition 12.7. One has dI(M,N) = dI(M̄, N̄). — Dey & Wang §12.4.1, Proposition 12.7, p. 378

Taken with Fact 12.2, this is the shape of §12.4's whole strategy: trade generality for computability. On the interval decomposable class the summands are nameable, so a matching makes sense and a polynomial-time algorithm becomes possible; Fact 12.2 then relates the computed number back to the interleaving distance, from above. The algorithmic machinery that follows — intersection modules, valid and trivialisable components, the candidate set and Theorem 12.16 — is §12.4.2 and §12.4.3, and is deferred.

Self-check 3. Why is the bottleneck distance at least as large as the interleaving distance?

The inequality is a statement about which set of witnesses is larger. Every δ-matching yields a δ-interleaving, so the set of δ that work for interleaving contains the set that work for matching, and its infimum is therefore no larger. The freedom an interleaving has and a matching lacks is to send one summand's content into several summands at once.

Self-check 4. A practitioner reports db(M,N) = 12 between two two-parameter modules. What follows?

One-sided bounds are one-sided. A small db certifies closeness; a large db certifies nothing, because the matching may simply have failed to find the mixing that a genuine interleaving would exploit. The third option is a category error — the algorithm's hypothesis is a property of the input to be verified beforehand, and it produces a number either way.

Self-check 5. What does §12.3 actually establish about the matching distance?

The section states stability and gives an algorithm; it does not display a comparison inequality, and this lesson does not supply one. The third option contradicts tda2-03 outright — no finite computable complete invariant exists for d ≥ 2, so no computable distance can separate all non-isomorphic modules.

Guided proof

Prompt. Prove that dI is symmetric and satisfies dI(M,M) = 0, directly from Definitions 12.7 and 12.8. Then prove the triangle inequality in the following form: if M and N are δ1-interleaved and N and P are δ2-interleaved, then M and P are (δ1+δ2)-interleaved. Conclude dI(M,P) ≤ dI(M,N) + dI(N,P).

Hint: for the triangle inequality, compose the interleaving maps and check that the composite families still satisfy both commutativity conditions, tracking the shifts.

Click to reveal model answer

Symmetry. Definition 12.7 is symmetric in M and N by construction: a δ-interleaving is an unordered pair of families (φ, ψ), and swapping their roles exchanges M with N while preserving both conditions. So the set of δ witnessing an interleaving is the same for (M,N) as for (N,M), and the infima agree. ∎

Vanishing on the diagonal. Take δ = 0. Then δ⃗ = 0⃗, and the identity families φx = ψx = 𝟙 : Mx → Mx are a 0-interleaving of M with itself: triangular commutativity holds because the composite is the identity, which is the structure map ρMx→x; rectangular commutativity is the statement 𝟙 ∘ ρM = ρM ∘ 𝟙. So 0 belongs to the set over which the infimum is taken, and dI(M,M) = 0. ∎

Triangle inequality. Let (φ, ψ) be a δ1-interleaving of M and N, and (φ′, ψ′) a δ2-interleaving of N and P. Write δ = δ1 + δ2 and define

Φx = φ′x+δ⃗1 ∘ φx : Mx → Px+δ⃗,   Ψx = ψx+δ⃗2 ∘ ψ′x : Px → Mx+δ⃗.

Rectangular commutativity for Φ. For x ≤ y, apply rectangular commutativity of φ to get φy ∘ ρMx→y = ρNx+δ⃗1→y+δ⃗1 ∘ φx, then rectangular commutativity of φ′ at the shifted indices to move φ′ across ρN. Composing, Φy ∘ ρMx→y = ρPx+δ⃗→y+δ⃗ ∘ Φx. The argument for Ψ is identical with the roles reversed.

Triangular commutativity. Compute Ψx+δ⃗ ∘ Φx. Inserting the definitions and using triangular commutativity of (φ′, ψ′) to collapse the inner pair into ρN shifted by 2δ2, then rectangular commutativity of ψ to move that structure map out, and finally triangular commutativity of (φ, ψ), the composite becomes ρMx→x+2δ⃗. Symmetrically for Φ ∘ Ψ.

Hence M and P are (δ1+δ2)-interleaved. Taking infima, for any δ1 > dI(M,N) and δ2 > dI(N,P) we get dI(M,P) ≤ δ1 + δ2, and letting both tend to their infima gives dI(M,P) ≤ dI(M,N) + dI(N,P). ∎

What was not proved. That dI(M,N) = 0 implies M ≅ N. That is a genuine separation axiom and it does not follow from the above — which is why dI is in general called an extended pseudometric until further hypotheses are imposed. Notice also that nothing in the argument mentioned d: the proof reads identically for any number of parameters, which is the same robustness the definition itself displayed.

Check your mental skeleton

If you can say: (1) a persistence module is a functor ℙ → Vec, morphisms are natural transformations, and a δ-interleaving is a pair of families φ, ψ into the δ-shift satisfying triangular and rectangular commutativity — with d appearing only in the shift vector and the index poset; (2) computing r with dI ≤ r < 3 dI is NP-hard for graded matrix representations, which is approximation-hardness, not undecidability; (3) dm is a weighted supremum over lines, polynomial for two parameters, stated stable with respect to dI without a displayed inequality; db needs a decomposition into nameable summands, so it lives on the interval decomposable class, and Fact 12.2 gives dI ≤ db — a small db certifies closeness and a large one certifies nothing — then you have the lesson.
