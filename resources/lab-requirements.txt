# The `lab` module's Python environment, resolved and frozen 2026-08-13.
#
# Why this file is committed rather than documented. `lab` problem sets record
# real program output as their worked answers, so an output is only meaningful
# next to the environment that produced it. The repo's own interpreter is
# Python 3.13.5 and carries gudhi 3.11.0, ripser 0.6.14 and scikit-learn 1.8.0 —
# different versions from these — so rebuilding from an unpinned install can
# reproduce the code and not the numbers, with nothing on the page to show that
# the environment moved. giotto-tda additionally publishes no wheel for 3.13,
# which is why the module runs on a separate 3.11 interpreter at all.
#
# Rebuild. The interpreter `uv venv` creates sits at a different path on each
# platform — `bin/python` on Linux and macOS, `Scripts/python.exe` on Windows —
# and this file was written from a Windows machine, so both are given. CI runs on
# Ubuntu, and anyone reproducing the full gate there needs the first form:
#
#   uv venv --python 3.11.11 <somewhere>/labenv
#
#   # Linux, macOS
#   uv pip install --python <somewhere>/labenv/bin/python \
#       -r resources/lab-requirements.txt
#
#   # Windows
#   uv pip install --python <somewhere>/labenv/Scripts/python.exe \
#       -r resources/lab-requirements.txt
#
# Verify, per problem set — this is gate 9, and it checks the pins in each
# set's ```env``` block against what the interpreter actually has installed.
# `$LAB_PYTHON` is the default for `--python`; the inline-assignment form is
# POSIX shell only, so the Windows line passes the flag instead:
#
#   # Linux, macOS
#   LAB_PYTHON=<somewhere>/labenv/bin/python \
#       python scripts/check_lab_outputs.py problems/sets/lab-01.md
#
#   # Windows
#   python scripts/check_lab_outputs.py problems/sets/lab-01.md \
#       --python <somewhere>/labenv/Scripts/python.exe
#
# The direct dependencies are the seven below the line; everything else is the
# transitive closure, pinned because a resolver is free to move it and the
# recorded outputs are not free to move with it.
