# S4 content build — plan and tracker

**Goal.** Every S4 unit gets its two content artifacts: a problem set
(`problems/sets/<unit>.md`) and a lesson (`lessons/<module>/<unit>.html`),
each passing the gates in `curriculum/LESSON-RUBRIC.md`.

**Scope.** 23 units — at2 (8), tda2 (11), cap (4). At start: 3 problem sets
exist (at2-07, tda2-02, tda2-10, written for the Stage-2 drift test), 0 lessons.

**Order.** Hardest semester first (S4, then S3, S2, S1 as separate programmes).
Within S4, DAG order — at2 → tda2 → cap — because later lessons cite earlier
ones and the problem sets interleave backwards.

**Branch.** `s4-content`, off `drift-stage2` (which carries the S4 syllabus and
the three drift problem sets, PR #10).

---

## Per-unit procedure

1. **Extract** the source sections named in the unit's `resources`, from the
   per-page markdown (`scratchpad/pull.py <book> --pages A-B`). Read them.
   Never write from recollection — LESSON-GUIDE §Source discipline.
2. **Problem set** (if absent): 5 problems, easy→hard, each with
   `Nudge` / `Strategy` / `Partial` / `Worked start` `<details>` blocks, every
   cited theorem/definition id verified present in the extract. Interleave
   earlier units where the syllabus prereqs invite it.
3. **Lesson**: `lessons/<module>/<unit>.html` from `lessons/_template.html`,
   following LESSON-GUIDE §Structure exactly. Read the problem set *first* —
   every technique it uses must be demonstrated by a worked or faded example,
   and every id it names must appear (Gate 0.1).
4. **Gates**:
   ```
   python scripts/check_lesson_coverage.py problems/sets/<u>.md lessons/<m>/<u>.html
   python scripts/lesson_lint.py lessons/<m>/<u>.html
   python -c "from html.parser import HTMLParser; HTMLParser().feed(open(PATH,encoding='utf-8').read())"
   grep -n "http://\|https://\|<link\|src=" lessons/<m>/<u>.html   # must be empty
   ```
   Then a Gate 2 read-through against the extract: every definition, theorem
   statement, proof step, worked answer, `data-ok` and model answer.

**Citations.** The corpus cites **printed** page numbers (verified: Abbott
Example 2.2.5 is printed p. 40 = PDF p. 52). The per-page markdown begins with
the printed number, so quote that, not the `page-N` directory index.

## Open decisions

- **tda2-02: RESOLVED — the accepted candidate was promoted.** The Stage-2
  drift test produced two ACCEPT candidates for this unit; the 12/12 one
  (`tda2-02-m3.html`, unblinded as Luna Max) is now `lessons/tda2/tda2-02.html`.
  Gate 0 re-run on promotion: coverage clean, lint 14/14, HTML parses, tags
  balance, zero external requests, inline JS parses. It is the one unit of S4
  not in the house voice, which is the accepted cost of using the rubric for
  what it was built for.
- **cap has no book source. RESOLVED — binding agreed 2026-08-09.** Its
  `resources` are `self-directed`, `tdlbook.org` and `Expository Writing
  folder`. These four are process units, so source discipline binds against
  three things and each lesson says which for every claim: (1) repo artifacts
  — MISSION.md, LESSON-RUBRIC.md, RESOURCES.md; (2) theorems already proved
  in this curriculum, cited to their texts with verified pages; (3)
  tdlbook.org, cited for what it is. Problem sets keep the five-problem shape
  but ask for written artifacts, the Worked start being a model fragment
  rather than a solution. cap-03 takes the TDL project's
  `results/trajectory_tda_integration` as its object.

- **tdlbook.org is not what the cap mission strips assume.** Fetched
  2026-08-09. It is *Topological Deep Learning: Going Beyond Graph Data* —
  combinatorial complexes, CCNNs, higher-order message passing — and contains
  no persistent homology, no filtrations or stability theorems, no study
  design, and no null models. Mapper appears only as a pooling operation
  (§7.4, §9.4, App. E). `resources/RESOURCES.md` files it correctly as a
  Semester-4 companion, but the syllabus attached it to cap-01/02/03 across a
  name collision: **"TDL" in cap-02's title is the TDL project of MISSION.md,
  a persistent-homology pipeline, not Topological Deep Learning.** Each cap
  lesson carries a warn block recording what the book does and does not
  supply. Worth a syllabus `resources` correction in a separate pass — not
  done here, since this branch is content-only.
