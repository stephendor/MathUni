# S2 content build — plan and tracker

**Goal.** Every S2 unit gets its two content artifacts: a problem set
(`problems/sets/<unit>.md`) and a lesson (`lessons/<module>/<unit>.html`), each
passing the eight gates below and the rubric in `curriculum/LESSON-RUBRIC.md`.

**Scope.** 31 units — `top` (13), `an2` (9), `lab` (9). At start: **0 problem
sets, 0 lessons** for all three modules; `lessons/top`, `lessons/an2` and
`lessons/lab` do not exist. Nothing is inherited; every artifact is new. Every
S2 unit has a `mission_link` in `syllabus.yaml`; none is missing.

**Branch.** `s2-content`, cut from `main` at `17b7101` on 2026-08-11, after
PR #16 (the tda1 module) merged. All of S1's shipped units, S3 and S4 are
therefore present and may be cited. Content-only: **no syllabus edits, no gate
edits.** Resource problems are recorded under Open decisions and handed to a
separate syllabus pass — S2 generates more of these than any previous semester.

**Order.** `top → an2 → lab`.

`top` first is forced by both dependency and evidence. It is the only S2 module
whose sources needed no adjudication at all — Munkres and Hatcher are both in
`bookmap.json` with per-page markdown — and four already-shipped S3 units cite
`top` units by number. `an2` second: its sources were missing at the start of
this session and are now settled (see Open decisions), and five S3 units depend
on it. `lab` last, because it is the module whose *shape* is new — its artifact
is code rather than proof, and neither LESSON-GUIDE nor LESSON-RUBRIC has a line
about that.

## Per-unit procedure

1. **Extract.** Pull the sections named in the unit's `resources` from the
   per-page markdown (`scratchpad/pull.py <Book> <pdfA> <pdfB> [out.md]`) and
   read them. Never write from recollection (LESSON-GUIDE §Source discipline).
   **Cite printed page numbers, and read the folio off the page you cite** —
   verify the offset yourself rather than assuming one. Record in the source map
   below **how the extract was actually taken**, filled in after the extraction,
   never in advance.
2. **Problem set** `problems/sets/<unit>.md`: 5 problems, easy→hard, each with
   `Nudge` / `Strategy` / `Partial` / `Worked start` `<details>` blocks; every
   cited theorem/definition id verified present in the extract. Interleave
   earlier units where the prereqs invite it. **LaTeX is the convention in
   problem sets.**
3. **Lesson** `lessons/<module>/<unit>.html` from `lessons/_template.html`,
   following LESSON-GUIDE §Structure. Read the problem set *first* — every
   technique it uses must be demonstrated by a worked or faded example and every
   id it names must appear (gate 1). **Literal Unicode maths in lessons, never
   LaTeX.**
4. **Gates** — all eight (below).
5. **Gate 7 read-back** against the extract: every definition, theorem
   statement, proof step, worked answer, `data-ok` and model answer, checked
   against the page it cites, **and against what the page *does* with the
   material** — proves, states, sets as an exercise, disclaims. This is where the
   real defects are; in S3 it caught the persistence algorithm attributed to the
   wrong section and an unread mechanism asserted as fact.
6. **Commit by explicit path, updating this file's tracker row to ✓ in the same
   commit.**

### Record modality, not only location

Every source row in the map below carries a **modality** — `proves`, `states`,
`sets-as-exercise`, `disclaims`, `applies` — because a citation that verifies
where a result lives does not verify what the text does with it, and the lesson's
verb ("Munkres proves", "Lindström sets") is checkable only against a recorded
field. Three of this session's audit findings were modality errors, not location
errors; see Open decisions. This follows open observation
`2026-08-10-source-asserts-what-it-only-states`.

## The eight gates

Gates 1–6 and 8 are executable; **gate 7 is a manual read-back**. Run from the
repo root, per unit:

```bash
python scripts/check_lesson_coverage.py problems/sets/<u>.md lessons/<m>/<u>.html
```

```bash
python scripts/lesson_lint.py lessons/<m>/<u>.html
```

```bash
python -c "from html.parser import HTMLParser; HTMLParser().feed(open('lessons/<m>/<u>.html',encoding='utf-8').read())"
```

```bash
python <scratchpad>/gate.py lessons/<m>/<u>.html
```

```bash
python <scratchpad>/mission.py lessons/<m>/<u>.html
```

Gates 1–3 are the built-ins: coverage, lint, HTML parses. Gates 4–6 are
`gate.py` — tag balance, no external requests, `node --check` on every inline
`<script>` — each of which caught a real S4 defect that the built-ins miss.
Gate 8 is `mission.py`. `gate.py`, `mission.py`, `pull.py` and `build.py` are
**not in the repo**; they were copied into this session's scratchpad from the S3
session's. Promoting them into `scripts/` has now been deferred three times and
is proposed under Open decisions.

### Negative controls — both re-run 2026-08-11, before any authoring

**gate.py — fires.** `negctl.html`, carrying a crossed `<sup>x</sub>`, an
`https://…cdn` link and a stray `;;)` inside an IIFE, returns three FAIL lines
and exit 1. The positive control (`lessons/tda1/tda1-09.html`) returns three PASS
lines and exit 0.

**mission.py — the inherited control was not a control, and has been replaced.**
`mission_negctl.html` exits 1, which the S3 plan recorded as evidence the gate
can fire. It is not. The script derives the unit id from the filename with
`([a-z0-9]+-\d+)\.html$`; `mission_negctl.html` does not match, so
`re.search(...)` returns `None` and the script raises `AttributeError` at line 7
**before the mission strip is ever compared**. Exit 1 came from a traceback, not
a verdict. A real control was built this session — a shipped lesson copied to
`negctl/tda1-09.html` with four words appended inside `<p class="mission">` — and
it returns `FAIL tda1-09 mission strip verbatim`, exit 1, printing both strings.
That is the watched failure; the positive control returns
`PASS tda1-09 mission strip verbatim`, exit 0. Logged as
`2026-08-11-mission-negctl-crashes-instead-of-firing`.

> **A non-zero exit is not a watched failure.** Accept a control only on the
> printed FAIL line naming the check. A crash, a missing file and a bad argument
> all exit 1 too.

### Gate 7 — the canvas actually renders

`node --check` proves a script *parses*, not that it *draws inside the viewport*.
`cap-04` shipped a diagram laid out at y = 334–368 inside a 340 px canvas —
clipped, silent, green on every other gate. So: compute node positions on paper
and check them against the canvas height before writing the script, then open the
lesson in the browser pane and read back the painted bounding box with a
`getImageData` alpha scan. **Leave real margin** — 7 px was too thin once and the
canvas had to be resized.

### Known gate defect — do not repair it by reflowing prose

`check_lesson_coverage.py`'s `REF_PATTERN` uses `\s+` between keyword and number,
and `\s+` eats newlines, so a citation wrapped across lines ("Theorem\n1.6")
produces an unmatchable ref and a false failure. It fired three times in S3.
Reflowing the prose makes it go away and is **the wrong repair**. Logged OPEN as
`2026-08-10-coverage-gate-breaks-on-wrapped-citations`; add recurrence evidence
there if it fires again.

### What the gate suite does not do

Every executable gate answers "is this well formed?" and none answers "is this
right?" A full green board is seven instances of one kind of confirmation, not
seven independent ones (`2026-08-10-gates-check-syntax-never-sense`). Two further
consequences specific to S2:

- **The problem set receives no automated check of any kind.** The `<details>`
  blocks are graded content; a `Partial` hint that states a falsehood passes
  everything. Give them the same read-back as the lesson body.
- **`lab` will trip gate 1 into vacuity.** A problem set that cites library APIs
  rather than numbered results yields `UNCHECKED checked 0 refs`, which exits 0.
  Where a lab set does cite numbered results from Edelsbrunner or Oudot, run the
  gate with `--min-refs` set to the count actually cited so the denominator is
  enforced rather than merely reported.

### The `lab` environment

`lab` problem sets contain runnable Python, executed, with real output recorded
as the worked answer (decision of 2026-08-11). Source discipline for a library
becomes: **pinned version + the API surface verified by execution**, cited as
e.g. `gudhi 3.13.0, RipsComplex.create_simplex_tree`. "Every worked example
computes the right answer" becomes "this code was run, in this environment, and
produced this".

The repo's own Python is **3.13.5**, and **giotto-tda publishes no wheel for
3.13** — the only artifact pip offers is a 0.1.4 source tarball. Since giotto-tda
is the first-listed source for six of the nine `lab` units, verification runs in
a dedicated interpreter instead. Registry entries for Python 3.10 and 3.11 exist
on this machine but both point at uninstalled paths; `uv` supplies a managed
3.11 without a system install:

```bash
uv venv --python 3.11 <scratchpad>/labenv
```

```bash
uv pip install --python <scratchpad>/labenv/Scripts/python.exe giotto-tda kmapper gudhi ripser persim
```

Built and verified 2026-08-11 — **Python 3.11.11 · giotto-tda 0.6.2 ·
kmapper 2.1.0 · gudhi 3.13.0 · ripser 0.6.15 · persim 0.3.8 ·
scikit-learn 1.3.2 · numpy 1.26.4**, all importing. Two notes for whoever rebuilds

## Mission-strip rescoping

Several `mission_link` strings claim more than their own sources establish. The
rubric requires the strip **verbatim** (gate 8), so quote it verbatim — then
teach only what the source supports and say so twice: a `.warn` block in the body
and a "Not established here" clause in the footer. Five of tda1's nine needed
this; tda2-07 is the model.

**Rescope in the open. Do not fill from recollection, and do not ship a
`NOT IN SOURCE:` marker either** — `lesson_lint.py` fails on the marker, and it
is a placeholder, not a resolution. **Do not soften the quotation to make it
true.**

Watch for it specifically at:

- **`top-07`**, whose strip asserts "Path components ARE what zeroth homology
  counts". Munkres §23–25 contains no homology at all, and the identification is
  false in general for arbitrary topological spaces — the strip's own hedge ("for
  TDA's finite complexes") is the part that is true and the part Munkres cannot
  supply. Bound it to what §25 proves about components and path components, and
  route the homology claim to `at1-07`.
- **`top-11`**, whose strip is about persistence diagrams and their limits, from
  a source (§31–32) with neither.
- **`top-05`**, whose strip reaches into multiparameter persistence.
- **`an2-01`**, whose strip — "The space of persistence diagrams is a metric
  space; fluency here is fluency there" — is the exact claim `tda1-05` established
  that *neither of its own sources defines*. `an2-01` teaches the axioms and the
  checklist; it does not get to assert the diagram-space metric, which is
  `tda1-06`'s.
- **`lab-03`**, whose strip says "reducing boundary matrices IS computing
  homology (aa-18 made runnable)" while `aa-18` is unwritten.

**Never carry a theorem number across books.** Munkres, Hatcher and Lindström
number the same results differently; re-derive every number from the book being
cited. And **for every "every", "any", "no", "always", "never" in prose, run the
degenerate list** — empty, one point, finite, discrete, indiscrete, trivial group
— before writing the sentence. Across both CodeRabbit rounds on the S3 branch the
unhedged universal in explanatory prose was the single largest defect category,
and it cites nothing, so it passes every gate
(`2026-08-10-unhedged-universals-pass-every-gate`).
